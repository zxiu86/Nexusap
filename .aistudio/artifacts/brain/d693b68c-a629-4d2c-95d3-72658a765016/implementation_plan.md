# تشغيل واختبار محرك التنظيف الحقيقي (MTX Live Inpainting Engine)

خطة هندسية متكاملة لربط وتشغيل محرك التنظيف الأصلي (MTX Native Engine) بشكل حقيقي وملموس، وتنفيذ اختبار إزالة علامة مائية حقيقي على صورة مدموغة بـ `olympustaff.com` داخل لوحة المشرف، مع الحفاظ على الأسماء الأصلية للمكتبات `libmtx_v8a.so` و `libmtx_v7a.so`.

---

## مراجعة المستخدم والقرارات الحاسمة (User Review & Critical Decisions)

> [!IMPORTANT]
> تم تأكيد القرارات الرئيسية بناءً على إجاباتك ومتطلباتك الدقيقة:

- **القرار المؤكد 1: اختبار حقيقي ومباشر لعلامة `olympustaff.com`:**
  استبدال الفحص النصي الروتيني بفحص حقيقي عملي؛ حيث يتم توليد/تحميل صورة تجريبية حقيقية مدموغة بختم الموقع المستهدف `olympustaff.com`، وتمريرها عبر مقبض المحرك الأصلي `nativeProcessBitmap` / `cleanImage`، وعرض النتيجة البصرية للمشرف (قبل وبعد المعالجة جنبًا إلى جنب) مع قياس المللي ثانية الحقيقي.
- **القرار المؤكد 2: الالتزام الصارم بأسماء المكتبات الأصلية:**
  المكتبات ستحافظ على أسمائها الصريحة المحددة: `libmtx_v8a.so` (لمعمارية 64-bit arm64-v8a) و `libmtx_v7a.so` (لمعمارية 32-bit armeabi-v7a). يتم ضبط `OlympusCleanerEngine` ومسار الاستخراج والتحميل ليكون ترتيب البحث والأولوية الأولى لهذه الأسماء بالتحديد.
- **القرار المؤكد 3: عدم التزييف والشفافية الكاملة للمحرك:**
  لن يحتوي الفحص على أي أرقام عشوائية أو نتائج وهمية (No Mock / No Simulation). يتم قفل البكسلات ومعالجتها فعلياً عبر JNI واستخراج النتائج المباشرة.

## 1. النظرة العامة وجوهر الفكرة (Overview & Core Concept)

- **ما الذي تقدمه هذه الميزة:**
  تمكين المشرف في شاشة "لوحة الإدارة" (Admin Dashboard) من اختبار المحرك الأصلي بشكل مرئي وتفاعلي. يرى المشرف صورة بدقة حقيقية عليها ختم مائي صريح لـ `olympustaff.com`، ويضغط زر الفحص، فيقوم المحرك بقفل الذاكرة الأصلية ومعالجة الختم وإزالته بدقة، ويظهر للمشرف الفرق بالعين المجردة مع مؤشرات الأداء الحقيقية.
- **الفئة المستهدفة:**
  إدارة التطبيق والمطورون للتحقق من سلامة تحميل المحرك على أجهزة المستخدمين والتأكد من توافق المعمارية وسلامة خوارزميات إزالة العلامات المائية.
- **القيمة الأساسية:**
  الثقة واليقين البرمجي التام بأن المحرك الأصلي C++/NDK يعمل بكامل كفاءته وخوارزمياته دون الاعتماد على افتراضات.

## 2. تجربة المستخدم والتصميم المرئي (User Experience & Visual Design)

### تدفق تجربة المشرف (Admin Flow):
1. **دخول قسم محرك التنظيف:** داخل تبويب "محرك التنظيف (MTX Engine)" في لوحة الإدارة.
2. **معاينة بطاقة الاختبار الحي:** يظهر قسم تفاعلي فاخر يحتوي على:
   - صورة الإدخال التجريبية (Original with `olympustaff.com` watermark badge).
   - حالة المحرك الحالية (Loaded / Architecture / Engine Version).
3. **بدء الفحص (Live Processing):**
   - الضغط على زر "تشغيل الفحص الحقيقي على ختم olympustaff.com".
   - ظهور مؤشر تحميل نابض مع تتبع زمني فوري.
4. **عرض النتائج المقارنة (Visual Comparison):**
   - عرض الصورتين (قبل التنظيف وبعد التنظيف) مع ميزة التكبير أو التمرير المقارن.
   - بطاقة تشخيص خضراء توضح: مدة المعالجة بالمللي ثانية، اسم المكتبة النشطة المحملة في الذاكرة (`libmtx_v8a.so` أو `libmtx_v7a.so`)، وإصدار JNI C++ الفعلي.
   - سجلات JNI التفصيلية قابلة للنسخ أو التوسيع.

### الهوية المرئية (Visual Style):
- **الألوان:** نمط فاخر داكن منسجم مع تصميم Nexus (خلفيات كحلية داكنة `#0F172A`، تدرجات ذهبية `#F59E0B`، ولمسات خضراء زمردية `#10B981` للنجاح).
- **العناصر:** بطاقات ذات حواف دائرية (16.dp)، تباين مريح للعين، وبطاقات مقارنة بصرية جنباً إلى جنب مع شارات واضحة (قبل / بعد).

## 3. القرارات التقنية والمفاضلات (Key Product Decisions)

- **القرار 1: أولوية محمل المكتبات (Library Loading Order):**
  - *النهج المختار:* تقديم `mtx_v8a` و `mtx_v7a` في مصفوفة المرشحات `candidates` لتسبق أي اسم بديل، والبحث المباشر عن `libmtx_v8a.so` و `libmtx_v7a.so` داخل مجلدات التطبيق الخاصة (`nexus_native_libs` ومكتبات APK).
  - *السبب:* تلبية طلبك بدقة بالمحافظة على الأسماء الأصلية ومنع أي التباس بين التسميات القديمة والجديدة.
- **القرار 2: صورة الاختبار الحقيقي:**
  - *النهج المختار:* إنشاء لوحة اختبار ذات تباين عالٍ بنمط صفحات المانهوا الملونة مع ختم احترافي يحمل النص والموقع المستهدف `olympustaff.com`.
  - *السبب:* محرك MTX الأصلي يتضمن خوارزمية تطابق (`TargetMatcher`) مصممة خصيصاً للتعرف على `olympustaff.com` وتطبيق `inpaintAdaptiveHybrid`.

## 4. البنية التقنية ومخطط النظام (Technical Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   واجهة لوحة الإدارة (Admin Dashboard)                  │
│                                                                        │
│   [ زر: تشغيل الفحص الحقيقي ] ───► يعرض صورة قبل / بعد + زمن JNI        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   OlympusCleanerManager & Engine                       │
│                                                                        │
│ 1. استدعاء loadNativeLibrary() بأولوية: libmtx_v8a.so / libmtx_v7a.so  │
│ 2. إنشاء مقبض أصلي: nativeCreate(...) عبر JNI                          │
│ 3. إعداد صورة ARGB_8888 مع ختم صريح: "olympustaff.com"                 │
│ 4. استدعاء المعالجة الأصلية: nativeProcessBitmap(handle, in, out)      │
│ 5. تسجيل واحتساب زمن التنفيذ والذاكرة وإرجاع النتيجة البصرية           │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ JNI Bridge (C++)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│             libmtx_v8a.so / libmtx_v7a.so (Native MTX Core)            │
│                                                                        │
│ • TargetMatcher: التحقق من القواعد ومطابقة "olympustaff.com"           │
│ • MaskGenerator: توليد القناع النقطي للعالمة المائية                   │
│ • HybridInpainter: الترميم التكيفي الهجين MultiScale PatchMatch        │
└────────────────────────────────────────────────────────────────────────┘
```

### خطة التحقق والاختبار (Verification Strategy):
- تجميع التطبيق بنجاح عبر `compile_applet`.
- التأكد من عدم وجود أي خطأ في تصدير دوال JNI.
- تجربة الضغط على زر الاختبار والتأكد من توليد الصورتين وحساب الوقت وعرض بطاقة النجاح.
