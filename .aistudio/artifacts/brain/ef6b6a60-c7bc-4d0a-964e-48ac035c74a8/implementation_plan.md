# خطة نظام التجهيز الإلزامي للموارد ومحرك التنظيف (v2.1.9)

خطة متكاملة لبناء نظام إعداد الموارد الإلزامي عند أول تشغيل للتطبيق، وتنزيل حزم محرك **Olympus MTX** تلقائياً من مستودع GitHub الرسمي (`zxiu86/nexusap`)، مع ترقية إصدار التطبيق رسمياً إلى **v2.1.9**.

---

## مراجعة المستخدم والقرارات المؤكدة (Confirmed Decisions)

> [!IMPORTANT]
> تم تأكيد الخيارات التالية بناءً على إجابات المستخدم:
> - **مستودع GitHub للموارد والمحرك:** مستودع التطبيق الرسمي (`zxiu86/nexusap`).
> - **إدارة انقطاع الإنترنت أو فشل التنزيل:** السماح للمستخدم بتصفح وقراءة المانجا مؤقتاً مع تعطيل ميزة التنظيف، وبمجرد استعادة الاتصال بالإنترنت ستظهر نافذة الإعداد التلقائي مجدداً لإكمال التثبيت.
> - **التحقق من سلامة الملفات:** التحقق من بنية أرشيف ZIP والتأكد من بصمة SHA-256 وسلامة رؤوس ELF للمكتبات المستخرجة.
> - **ترقية الإصدار:** رفع الإصدار من `2.1.8` إلى `2.1.9` (Version Code 59).

---

## 1. النظرة العامة والهدف الرئيسي (Overview & Concept)

- **الهدف:** توفير تجربة احترافية وسلسة تكتشف معمارية جهاز المستخدم تلقائياً (`arm64-v8a` أو `armeabi-v7a`)، وتسترجع أحدث حزمة متوافقة من محرك MTX (`libmtx_v8a.zip` أو `libmtx_v7a.zip`) من إصدارات GitHub مع إظهار الحجم الفعلي الحقيقي والتقدم اللحظي.
- **الأمان والاعتمادية:** منع أي تشغيل أو تنظيف للمانجا قبل التحقق التام من صحة وسلامة الحزمة عبر SHA-256، وتثبيتها وفحصها بنجاح داخل الذاكرة بواسطة `OlympusCleanerEngine`.

## 3. خطة التنفيذ خطوة بخطوة (Implementation Steps)

### المرحلة 1: ترقية إصدار التطبيق (Version 2.1.9)
- تحديث `app/build.gradle.kts`:
  - `versionCode = 59`
  - `versionName = "2.1.9"`
- تحديث `AppVersionConfig.kt`:
  - `VERSION_NAME = "2.1.9"`
  - `VERSION_CODE = 59`
  - تحديث سجل التغييرات الرسمي (`CURRENT_CHANGELOG_FEATURES`).
- تحديث اختبار `GitHubSyncUnitTest.kt` ليتطابق مع `2.1.9` و `59`.
- تحديث `metadata.json` لوصف الإصدار الجديد بدقة.

### المرحلة 2: محرك إدارة التجهيز والتحميل (ResourceSetupManager)
- إنشاء كلاس إدارة دورة الحياة وحالة التجهيز: `com.example.util.ResourceSetupManager`.
- تنفيذ الحالات:
  - `Idle`: في انتظار البدء.
  - `Discovering`: البحث عن أحدث إصدار في `zxiu86/nexusap` عبر GitHub API.
  - `MetadataReady`: تم جلب اسم الملف المتوافق، المعمارية، والحجم الفعلي بالبايت.
  - `Downloading`: تنزيل مع بث النسبة المئوية والبايتات المنزلة.
  - `Verifying`: فحص بصمة SHA-256 وسلامة ملف الـ ZIP.
  - `Extracting`: فك الضغط الآمن إلى مجلد التطبيق الخاص (`nexus_native_libs`).
  - `Initializing`: تحميل المكتبة وتشغيل الفحص التشخيصي الذاتي للمحرك.
  - `Success`: تم التثبيت بنجاح وتفعيل المحرك.
  - `Error`: خطأ مع رسالة توضيحية وإمكانية المحاولة مجدداً أو المتابعة بدون تنظيف.
- تخزين بيانات التثبيت في SharedPreferences لتفادي إعادة التنزيل على التشغيلات اللاحقة.
- مراقبة حالة الإنترنت عبر `NetworkMonitor`: إذا انقطع النت وتابع المستخدم، تظهر النافذة تلقائياً فور توفر الإنترنت لإكمال التثبيت.

### المرحلة 3: واجهة المستخدم (FirstLaunchResourceSetupDialog)
- إنشاء مكون Compose فاخر ومصقول: `com.example.ui.components.FirstLaunchResourceSetupDialog`.
- العنوان: **"تحميل المظاهر والإعدادات والتخصيص"**.
- عرض المعلومات الحقيقية والديناميكية:
  - حالة العملية (مع أيقونة ومؤشر تحميل متحرك).
  - المعمارية المكتشفة (`arm64-v8a` أو `armeabi-v7a`).
  - إصدار المحرك المستهدف.
  - حجم ملف المحرك الفعلي (بوحدات MB حقيقية مسترجعة من الخادم).
  - شريط التقدم التفاعلي (النسبة المئوية مع البايتات المحملة).
- معالجة حالات الخطأ بأزرار: "إعادة المحاولة"، وخيار "المتابعة بدون تنظيف" عند تعذر الاتصال مع التنبيه بظهور النافذة فور عودة الإنترنت.

### المرحلة 4: ربط النافذة في MainActivity وفحص الاعتمادية
- إدراج النافذة في `MainActivity` أو على مستوى الشاشة الرئيسية بحيث تظهر فوراً عند أول تشغيل إذا لم تكن الموارد مثبتة.
- ربط حالة التثبيت مع `OlympusCleanerManager` لتفعيل التنظيف فقط بعد اكتمال التجهيز بنجاح.
- إجراء فحص البناء الشامل عبر `compile_applet`.
